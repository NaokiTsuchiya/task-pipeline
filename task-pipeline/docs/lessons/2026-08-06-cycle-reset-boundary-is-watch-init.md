# リセット境界は状態を増やさず verb の呼び分けに置く

fix_attempts / handled は「同じ PR の周回をまたいで累積すべき」で、restore 後の再走では
「リセットすべき」。これを機械側で自動判別する案 (finalize の from を state に持たせる等)
は退けた — 判別のための状態を足すと、その状態自身が新しい継ぎ目 (壊れうる同期点) になる。

採った形: in-review は常に watch を保持し (壊さない側に固定)、リセットは watch-init だけが
行う。すると「どちらの周回か」の判断は SKILL.md の watch-init を呼ぶ/呼ばないの 1 箇所に
集約され、CLI は「どちらの列でも状態を壊さない」ことだけを保証すればよくなる。
判断は散文に 1 箇所、保全は機械側、という分担が今回の設計の芯。
