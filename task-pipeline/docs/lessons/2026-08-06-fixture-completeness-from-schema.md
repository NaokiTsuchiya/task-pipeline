フレームテストの検出力はフィクスチャの網羅性で決まる。網羅性自体をスキーマとの突き合わせで強制したら、既存フィクスチャの穴が即座に見つかった。

# フィクスチャの網羅性はスキーマから強制する

「verb が管轄外のフィールドを壊していないか」を diff で見るフレームテストは、
フィクスチャに存在しないフィールドの破壊を原理的に検出できない (無いものは diff に
現れない)。つまりサブ機械を 1 つ足したとき、フィクスチャへの追加を忘れると保護が
黙って効かなくなる — これはサブ機械追加の思考実験で見つけた唯一の「黙って通る」穴だった。

対策として、最大フィクスチャのキー一覧を state.schema.json のプロパティ一覧と突き合わせる
メタテスト (T-ALIGN-13) を足したところ、その最初の実行で既存フィクスチャの実穴
(rebaseOf に kind/cause/report が無い) が見つかった。「検査を検査する」層は理屈ではなく
実際に穴を拾う。スキーマにフィールドを足せばフィクスチャが強制的に追従し、フレーム保護が
自動で新フィールドに及ぶ。
