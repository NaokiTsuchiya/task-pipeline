# docs/history/metrics/ — 公開レトロ記録

## これは何か

`docs/metrics/` (パイプラインが実行のたびに書く、追跡外のレトロ記録) のうち、**人が選んで公開してよいと
判断したものだけ**を、追跡下の写しとしてここに置く。

## 何を置くか

- 追跡下のファイル (backlog・issue 等) が数字の根拠として引用している `docs/metrics/<UTC 日付>.md`。
  昇格しないと、その引用は clone した側から辿れない (`docs/metrics/` は `.gitignore` で除外されている)。

## 何を置かないか

- `docs/metrics/` の全件。昇格は自動化しない — 選ぶのは人である。
- 個人情報・絶対パス・認証情報を含むもの。`docs/metrics/` の記録は本来含まない設計だが、昇格前に目視で確認する。
- 誰にも引用されていない記録。引用が無いなら、追跡下に置く理由も無い。

## 昇格の手順 (人が行う)

1. `docs/metrics/<UTC 日付>.md` の中身を確認し、個人情報・絶対パス・認証情報が無いことを確かめる。
2. ファイルをそのまま (編集・要約せずに) `docs/history/metrics/<同じファイル名>` へコピーする。
3. その記録を引用している追跡下の箇所を、コピー先のパスを指すよう書き換える。

## 昇格した写しの性質

昇格した写しは **snapshot** である。以後 `docs/metrics/` 側の同名ファイルが上書き・追記されても、
この写しは追従しない (分岐する)。写しを最新化したくなったら、それは改めての昇格の判断であり、
自動では起きない。

## スコープ

この規約はこのリポジトリだけの取り決めである。`task-pipeline/references/retro.md` が定める
レトロサブエージェントの書き込み先 (`docs/metrics/`) は変えない — skill を使う他プロジェクトの挙動には
影響しない。
