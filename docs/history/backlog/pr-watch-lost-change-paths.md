# PR 追従の「検知したのに観測されない」3 経路を塞ぐ

## 背景 / 現状

行番号はコミット 3015e87 時点。ずれていたら引用文言で grep すること。対象は task-pipeline/SKILL.md「PR の追従 (finish=pr)」節と task-pipeline/references/pr-watcher.md。3 件とも本セッションの敵対的検証 (独立サブエージェントによる反証試行) で確定している (CONFIRMED)。

**(a) 観測 error で変化が永久に失われる。** SKILL.md 366 行は、watch プロセスの終了通知を受けた時点 (分岐前) で新署名を `watch.sig` に保存し、367 行で changed なら観測サブエージェントを起動する。観測が `error` を返した場合の規定 (396 行) は「そのイテレーションは何もしないだけで、追従は続ける」だけで、署名を戻す・再観測する規定が無い。張り直し (364 行) は保存済みの新署名を第 5 引数に渡すため、watch プロセスは次の外部変化が起きるまでブロックし続け、error 中に起きていた変化 (レビュー指摘等) は二度と観測されない。catch-up 観測の規定は「`watch.sig` が null のまま張り直すことになった場合」(364 行) に限定されている。396 行自身が「ネットワークや gh の一時的な不調が大半」と想定する一時的失敗が、恒久的な取り落としになる。

**(b) 検知窓と観測窓の不一致。** 署名スクリプト (task-pipeline/scripts/watch-pr.sh 50 行) はスレッド内コメントを `comments(last:20)` (新しい側 20 件) の updatedAt で検知するが、観測側 pr-watcher.md の GraphQL (73 行) は同じスレッドを `comments(first:5)` (古い側 5 件) しか取得しない。6 件以上コメントが付いたスレッドへの新しい返信は、検知はされるが観測に載らず、`clean` 判定で署名だけが消費される。同種の不一致は PR 直下コメント (署名 last:50 / 観測 last:30)、レビュー本文 (last:50 / last:20)、スレッド数 (first:100 / first:50) にもある (last 同士の組で実害が出るのは窓外の古い項目が編集されたときに限る)。README.md 47 行の「既存スレッドへの返信も検知対象 (いずれも実測確認済み)」は、5 コメント超のスレッドでは成立していない。

**(c) pr_fix 再開時の焼き込み。** SKILL.md 358 行の規定により、「レビュー待ちに入った直後」と「pr_fix の push 直後」の watch 起動は第 5 引数を渡さず `watch.sig` も null に戻す。この 2 起動には catch-up 観測の規定が無く (364 行の catch-up は張り直し経路限定であることを、359 行の管轄宣言「in_review に戻るときに張り直すので、ここでは張らない」まで遡って検証済み)、基準署名は起動時に新規取得されるため、pr_fix 実行中 (数十分かかりうる) にレビュアーが投稿したコメントは基準署名に焼き込まれる。CI が動くリポジトリなら rollup の遷移で後から起きるが、pr-watcher.md 56 行が明示サポートする `ci: "none"` のリポジトリでは以後署名が動かず、その指摘は観測されないままになる。

## 要求

watch-pr.sh (スクリプト本体) は変更しない (署名窓そのものの拡張は別タスク scripts-test-harness の管轄)。SKILL.md と pr-watcher.md の指示の修正で 3 経路を塞ぐ:

1. (a): 観測が `error` を返したとき、その変化が後続で必ず観測される規定を入れる。手段は実装で選んでよい (例: error 時に `watch.sig` を null に戻して次の張り直しの catch-up 観測を発火させる、または error からの復帰時に観測を再実行する)。error 3 回連続で `stopped` になる既存規定との整合を保つこと。
2. (b): pr-watcher.md の各取得窓を、watch-pr.sh の署名が変化を検知しうる範囲を包含するように直す (特にスレッド内コメントは新しい側を取る)。包含しきれない残余が残るなら、その旨と影響を pr-watcher.md に明記する。
3. (c): 「レビュー待ちに入った直後」「pr_fix の push 直後」の watch 起動の前または直後に、その時点までに届いていた指摘を回収する観測を 1 回行う規定を入れる (`handled` が重複を除くので、既対応の指摘が再浮上することはない)。

## 受け入れ条件

1. 「changed 通知 → 署名保存 → 観測 error → 以後外部変化なし」の机上トレースで、error 中に起きていた指摘が後続イテレーションで観測され fix 処理に到達することを、変更後の SKILL.md の文面だけから追える。
2. pr-watcher.md の GraphQL 取得窓と watch-pr.sh の署名窓 (48-50 行) を並べたとき、スレッド内コメントについて観測側が署名側の検知範囲 (新しい側 20 件) を包含している。包含できていない残余があれば、pr-watcher.md にその旨が明記されている。
3. 「pr_fix 実行中にコメント投稿 → finalize push → watch 再開」の机上トレースで、`ci: "none"` のリポジトリでもそのコメントが観測に載り、actionable なら fix 処理に到達することを、変更後の文面だけから追える。
4. README.md の検知対象の主張 (47 行相当) が変更後の仕様と矛盾しない (5 コメント超のスレッドでも成立するか、制限が明記されている)。
