# watch-pr.sh の署名が取得窓の外の変化を取り落とすのを直す

依存: test-harness-foundation

## 背景 / 現状

`task-pipeline/scripts/watch-pr.sh` の署名は GraphQL 1 回で取った次の成分から作られる (`jq_signature`、2026-08-02 時点):

```
.state, .headRefOid, statusCheckRollup.state,
comments.totalCount, reviews.totalCount,
(未解決 reviewThread の件数),
(comments / reviews / reviewThreads.comments の updatedAt の max)
```

取得窓は `comments(last:50)` / `reviews(last:50)` / `reviewThreads(first:100)` × スレッド内 `comments(last:20)` である。

**この窓の外で起きた変化は、署名のどの成分も動かさない。** 具体的には:

- PR 直下コメントが 51 件以上あるときの、最古側コメントの本文編集
- スレッドが 101 本以上あるときの、窓外スレッドの resolve / unresolve や新規投稿

`scripts-test-harness` の調査時 (2026-08-02) に、署名の jq をフィクスチャ JSON に対して実行し、**窓外編集の 2 入力で署名が完全一致すること** (対照: 窓内編集では変わること) を実測している。GraphQL の並び順 (orderBy 無指定の `comments` は作成順昇順、`reviewThreads` に orderBy 引数なし) も実 API で確認済みで、窓外の編集が `last` 窓に入り込むことはない。

署名が動かないので watcher は `timeout` で終わり、その指摘は**観測サブエージェントに一度も渡らない**。CI が動くリポジトリなら次の rollup 遷移でまとめて拾えるが、CI の無いリポジトリ (`ci: "none"`) では署名が動く要因が無く、永久に失われる。

なお `watch-pr.sh` 冒頭 (14-16 行付近) の「本文編集を取り落とさない (実測確認済み)」というコメントは、**窓内に限った主張**である。

## 要求

1. **窓外の変化も署名に載るようにする。** 例: `reviewThreads` の `totalCount` と resolve 済みスレッド数をクエリと署名に足す (スレッド本数の増減と、窓外を含む resolve 状態の変化が署名に反映される)。同様に、窓外コメントの件数変化が既に `comments.totalCount` / `reviews.totalCount` で載っていることを確認し、載っていない成分だけを足す。
2. **GraphQL 1 回・署名 1 行の形は維持する。** クエリを 2 回に分ける、ページングして全件を走査する、といった変更はしない (ブロッキング検出を安く保つのがこのスクリプトの存在理由である)。
3. **完全には閉じられない残余を明記する。** 上記の方法でも「窓外コメントの本文編集そのもの」は検知できない (件数も resolve 状態も動かないため)。残る穴をスクリプト冒頭のコメントに書き、同時に「本文編集を取り落とさない (実測確認済み)」の主張を実態に合う形へ限定する。
4. **先に FAIL するケースを書いてから直す。** `test-harness-foundation` のハーネス上に、窓外変化のフィクスチャ対を用いたケースを追加し、修正前のスクリプトでそれが FAIL する (= `timeout` になる) ことを確認してから修正に入る。
5. **外部挙動は変えない。** 終了コード (0 / 2 / 3 / 4) と stdout の形式 (`PR-WATCH <task> changed <旧> -> <新>` / `timeout <署名>`) は `task-pipeline/SKILL.md` の追従分岐が依存しているので、変更しない。署名の文字列そのものは変わってよい (state.json の `watch.sig` に保存されるだけで、意味を持つのは前回との一致・不一致だけである)。

## 受け入れ条件

1. 窓外変化のフィクスチャ対 (旧: PR 直下コメント 51 件相当かつスレッド 101 本相当、新: **窓外の resolve 状態またはスレッド件数だけが違う**) を与えると、`watch-pr.sh` が `exit 0` (`changed`) で終わるケースがハーネスにあり、PASS する。
2. **修正前のスクリプトでは条件 1 のケースが FAIL する (= `timeout` で `exit 2` になる)** ことを確認した記録が成果物にある (実行した実出力を含む)。
3. 窓内の変化 (新規コメント、既存スレッドへの返信、窓内コメントの本文編集) を与えたケースが引き続き `changed` になり、PASS する (対照が壊れていないこと)。
4. 変化が無い入力では引き続き `timeout` (`exit 2`) になる — 署名成分を足したことで**毎回 changed になる**ような退行が無い。同一入力を 2 回与えると署名が一致することをケースで固定する。
5. GraphQL の呼び出しが 1 周につき 1 回のままである (モック `gh` の呼び出し回数で判定する)。
6. `watch-pr.sh` 冒頭のコメントが、閉じられた範囲と残る穴 (窓外コメントの本文編集) を実態どおりに述べている。「本文編集を取り落とさない (実測確認済み)」の無条件な主張が残っていない。
7. 終了コードと stdout の形式に差分が無い (`git diff` で、それらを生成する箇所が変わっていないこと)。
8. `sh tests/run.sh` が全ケース PASS で exit 0。
