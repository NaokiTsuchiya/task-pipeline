# install.sh agents 節の symlink 検査をリンク所在基準に直す

## 背景 / 現状

install.sh の agents 節 (76-86 行、コミット 3015e87 時点) は、既存 symlink の検査でリンク先文字列を `ls -ld -- "$link" 2>/dev/null | sed -e 's/^.* -> //'` (79 行) で取り、その dirname を `CDPATH='' cd -P -- "$(dirname -- "$link_target")"` (80 行) で解決する。この cd は **install.sh 実行時のカレントディレクトリ**を基準に相対パスを解決するため、リンク先が相対パスの場合に実行場所で結果が変わる。本セッションのサンドボックス再現 (独立に 2 回) で 2 方向の誤判定を確認済み:

- (a) リンクの所在ディレクトリからは正しくリポジトリの agents ファイルに解決する相対 symlink (stow 系ツールが作る形) があると、その相対パスが解決できないカレントディレクトリから実行した場合に「warning: ... is a symlink not pointing to this repository — left untouched」+ exit 1 になる (偽警告)。
- (b) 実際には壊れている相対 symlink が、カレントディレクトリからは偶然解決する場所で実行すると「skip: agents/... (already installed)」+ exit 0 になり、壊れたリンクが放置されたまま成功報告される (冪等・安全という設計目標への直接違反)。

skills 節 (35-38 行) は `CDPATH='' cd -P -- "$link"` でリンク自身を辿るため正しい (リンク先がディレクトリだから使える手)。agents のリンク先はファイルなので同じ手は使えないが、解決の基準をリンクの所在ディレクトリにすれば同等になる。付随して、リンク先パスが ` -> ` を含む場合に greedy な sed が誤パースすることも確認済み (単独では稀だが、同じ検査の書き直しで一緒に消せる)。shellcheck 0.11.0 は 79 行に SC2012 (ls の出力パース) を出す。

このスクリプトは POSIX sh + POSIX 標準ユーティリティのみという制約がある (冒頭 15 行に明記。readlink 等の拡張は使わない)。

## 要求

agents 節の既存 symlink 検査を、リンク先の相対パスを**リンクの所在ディレクトリ (agents のリンク先ディレクトリ) 基準**で解決する実装に直す。POSIX sh 制約は維持する。判定の意味は現行どおり: このリポジトリの agents/*.md を指していれば skip、指していなければ警告して触らない。ls 出力のパースをやめられるなら併せてやめてよい (手段は問わないが POSIX の範囲で)。

## 受け入れ条件

検証は一時ディレクトリで行い、`~/.claude/` を汚さない (リンク先は第 1・第 2 引数で上書きできる)。

1. リンク所在ディレクトリからは正しくリポジトリの agents ファイルに解決する相対 symlink をリンク先ディレクトリに置き、その相対パスが解決できない別のカレントディレクトリ (例: /) から `sh install.sh <skills先> <agents先>` を実行すると、skip 判定かつ exit 0。
2. リンク所在からは壊れているが、あるカレントディレクトリからは偶然解決してしまう相対 symlink を置き、そのカレントディレクトリから実行すると、warning + exit 1 で、リンクは変更されない。
3. 従来の正常系が壊れていない: 空のリンク先で実行すると絶対パスの symlink が作られ exit 0、再実行で skip + exit 0、他所を指す絶対 symlink は warning + exit 1 (skills 節・agents 節とも)。
4. `sh -n install.sh` が exit 0 で、bash 拡張 (`[[`、配列等) を使っていない。
