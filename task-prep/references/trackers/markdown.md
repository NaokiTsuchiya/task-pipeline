# markdown backlog — task-prep のトラッカー操作

`source` はバックログの**リストファイル** (task-pipeline の markdown アダプタと同じもの。例: `./backlog/TASKS.md`)。タスク本文は 1 タスク 1 ファイルで同じディレクトリに置き、**ファイル名 (拡張子除く) が id**。id は kebab-case の短い slug にする。

## 状態の表現

| 状態 | 表現 |
|---|---|
| 準備完了 (パイプライン候補) | バックログ本体に `- [ ] <id>` で掲載 |
| 深掘り済み・依存待ち | アイテムファイルはあるがリスト未掲載で、本文に `依存:` 行がある |
| 下書き・人待ち (管轄外) | リスト未掲載で `依存:` 行なし |

- task-pipeline の markdown アダプタは**リストに載っていないアイテムファイルを無視する** (アダプタ仕様に明記された挙動)。リスト掲載がそのまま ready 兼依存ゲートになる。
- `未確定:` が残るアイテムはリストに載せない。依存だけが残るアイテムと違い、昇格スキャンでも載せない (人を待っている)。
- リストの並び = 実行順なので、複数を ready にするときは依存順 (依存される側が先) で追加する。

## 操作

- **既存タスクの取得** (深掘りの入力): アイテムファイル `<sourceのディレクトリ>/<id>.md` を読むだけ。
- **重複検索**: 同じディレクトリのアイテムファイル一覧とリストを見る。
- **作成** (分解の書き込み): アイテムファイルを書く (先頭 `# タイトル`、以下本文)。依存が無く ready 基準を満たすものだけ、バックログ本体の末尾に `- [ ] <id>` を追加する。
- **本文更新** (深掘りの書き込み): アイテムファイルを書き換える。
- **分解元の処置**: 既存アイテムを分解で置き換えたときは、承認後にリストの行を削除し、アイテムファイルの冒頭に `分解済み: <子id>, <子id>` の行を記す (ファイルは残してよい — リストに無いファイルはアダプタが拾わず、`分解済み:` 行を持つファイルは下記の昇格スキャンも対象外)。他のアイテムが `依存: <元id>` を持つなら、承認後に子へ張り替える。
- **依存チェック**: 依存 id が `## Done` セクションに `- [x] <id>` として載っていれば解決。まだ解決していなくても、その id のリスト行かアイテムファイルが存在するなら正常な未解決 (待てばよい — 依存待ちアイテムは定義上リスト未掲載なので、ファイルの存在まで見ること)。行もファイルも無い、またはファイルが `分解済み:` になっている場合だけ「前提が消えた」— 解決とみなさず、従属アイテムごとユーザーに上げる。
- **昇格スキャン**: リスト未掲載のアイテムファイルのうち `依存:` 行を持つもの (`分解済み:` 行を持つものは除く) を走査し、全依存が Done かつ `未確定:` が無いものをバックログ本体の末尾に追加する。
- **gate 宣言時の sha 記録**: `task-prep/SKILL.md`「gate 宣言 (light)」の `<!-- task-pipeline:gate=light -->` 行を入れるとき (新規作成・深掘りの本文更新のどちらでも) は、同じアイテムファイルに専用の 1 行 `<!-- task-pipeline:gate-verified-at=<sha> -->` を追加する (`<sha>` は `git -C <target project> rev-parse HEAD` の値)。既存の gate マーカーと同じ HTML コメント形式にし、アイテム本文の自由記述を汚さない。**既存の (sha未記録の) gate:light アイテムに遡って追記しない** — 今後新規に gate:light を付与するアイテムにだけ適用する。

書き込みはすべてローカルファイルなので、gh と違いドラフトディレクトリは要らない — アイテムファイル自体がドラフトを兼ねる (リストに載せるまでパイプラインからは見えない)。
