# skill インストールスクリプト (symlink 自動化)

## 背景 / 現状

- インストール手順は README.md の「インストール」節 (12-19 行目) に skill ごとの `ln -s` コマンドとして手書きされている。skill を追加するたびにこのブロックも手で増やす必要がある。
- リポジトリにはスクリプト・Makefile・CI が一切ない (トップレベルは README.md / backlog/ / prompts/ / task-pipeline/ / task-prep/ のみ)。
- skill ディレクトリの機械的な見分け方: リポジトリ直下で `SKILL.md` を直接含むディレクトリ (task-pipeline/SKILL.md, task-prep/SKILL.md)。backlog/ と prompts/ には SKILL.md が無い。
- 手作業ゆえのずれの実例 (2026-07-26 確認): `~/.claude/skills/` には task-pipeline の symlink だけがあり、README が並べている task-prep は未インストール。
- `~/.claude/skills/` にはこのリポジトリ外由来のエントリも同居している (takt: 実ディレクトリ、grill-me: 別リポジトリを指す symlink)。スクリプトはこれらを壊してはならない。

## 要求

リポジトリ直下に、SKILL.md を持つトップレベルディレクトリを列挙して `~/.claude/skills/` へ symlink するインストールスクリプトを追加する。skill を新規追加したとき、スクリプト本文や README のインストール手順を編集せず再実行だけで新 skill がインストールされること。

- 冪等: 既に正しい symlink があるものはスキップし、エラーにしない。
- 安全: リンク先の同名エントリがこのリポジトリを指していない場合 (実ディレクトリ、他を指す symlink) は上書きせず、警告を出して残りの skill の処理を続行する。
- テスト可能性: リンク先ディレクトリ (既定 `~/.claude/skills/`) を環境変数または引数で上書きできる。
- 形式: 依存ゼロの POSIX sh 単発スクリプト (POSIX sh + POSIX 標準ユーティリティのみ。bash 拡張や外部ツールに依存しない)。
- README.md のインストール節を、skill ごとのコマンド列挙からスクリプト実行 1 行の案内に置き換える。

## 受け入れ条件

前提: 検証はリンク先を一時ディレクトリに上書きして行える (ユーザーの `~/.claude/skills/` を汚さない)。

1. 空のリンク先ディレクトリに対してスクリプトを実行すると、SKILL.md を持つ全トップレベルディレクトリ (現時点では task-pipeline と task-prep) について `<リンク先>/<ディレクトリ名>` の symlink が作られ、それぞれリポジトリ内の該当ディレクトリを指す。終了コード 0。
2. 続けてもう一度実行しても終了コード 0 で、リンクの状態 (`ls -la` の結果) が変わらない。
3. リンク先に「リポジトリ外を指す同名エントリ」(実ディレクトリまたは別の場所への symlink) がある状態で実行すると、そのエントリは変更されず、警告が出力され、他の skill の symlink は作られる。
4. SKILL.md を置いた新しいトップレベルディレクトリを追加して再実行すると、スクリプト本文を編集していないのに、その skill の symlink も作られる。
5. README.md のインストール節に skill 名のハードコードが残っておらず、スクリプト実行の案内になっている。
6. 1-4 は `sh <スクリプト>` (POSIX sh) での起動で成立する。
